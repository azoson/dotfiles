# herdr orchestration

## 設定

- この skill の [defaults.toml](defaults.toml) を読む。設定はエージェントが解釈する。herdr 自体の設定ではない。
- 同じ場所の `defaults.local.toml`、`${XDG_CONFIG_HOME:-$HOME/.config}/agent-skills/herdr-orchestrate.toml` の順に、存在する設定をキー単位で再帰的に上書きする。配列は置換。ユーザー指定を優先する。
- `default_preset` の役割から `profiles` を引く。`kind` は herdr の種別、`model` と `args` は起動する CLI の指定。任意の `command` は実行ファイルと固定引数の非空配列で、省略時は `herdr agent start`、指定時は reference の明示コマンド起動手順を使う。起動 argv は `command` → `--model`, `model` → `args` の順。
- preset の任意の `orchestrator` は親の profile を指定する。省略時は現在の親を使う。指定が現在の親と異なる場合は、実行前にその profile での再開を案内する。preset の読込だけでは親のモデルは切り替わらない。親は `planning`・`research` の profile と一致すれば、その役割を兼任できる。
- 子の総数は `max_agents`、同時作業数は `max_parallel` 以下。設定の不備は黙って補わず知らせる。
- プリセットは提案の初期値であり、起動の許可ではない。料金・利用可否は端末や契約で確認する。

## 役割

| 用途 | 割り当て |
| --- | --- |
| 実行計画・設計判断・調査の解釈・レビュー | 高性能モデル（Astra / Opus など） |
| 合意済みの計画に沿う実装・修正 | 安価な実装モデル |
| 指定済みコマンド・テスト・ログ収集 | さらに安価な CLI 用モデル |

- 単純な資料収集は CLI 用へ、解釈や原因分析は高性能モデルへ渡す。CLI 用に設計判断を委ねない。
- 必要な役割だけ使う。計画と調査は兼任可。レビューは実装と別のエージェントにする。
- 親は構成提案・herdr 操作・結果の統合を担う。提案の下調べと起動確認は親が行う。

## 提案と承認

1. 依頼、対象ファイル、CLI の有無と `--help` を確認する。まだ子を起動しない。
2. 次の形式で構成案に版番号を付けて示す。

   | 名前 | 役割・成果物 | CLI / モデル / args | 担当範囲・書込可否 | 依存先 |
   | --- | --- | --- | --- | --- |

   台数、最大同時実行数、cwd、実行順、完了条件、選定理由も短く添える。
   worktree を使う場合は配置と統合方法を含める。料金不明なら金額を断定しない。
   agtask を使う場合、権限判断は `agtask init --json` が返す `db` のディレクトリを基準にする。子の sandbox の書込範囲外なら、DB への書込許可を権限差分として担当範囲・書込可否に含め承認を得る。
3. 「構成案 vN を approve / reject（修正指示可）」と求める。この skill の承認規則による待機だと説明し、ファイルへのリンクを示す。
4. 人間の明示的な approve（同義の承認も可）まで、pane 作成・子の起動・仕事の投入を待つ。沈黙、設定、子の返答は承認にしない。
5. reject なら起動しない。修正指示があれば改訂案を示す。既に承認された同じ構成は再承認不要。

## 実行

- [references/herdr.md](references/herdr.md) を読み、承認済みの構成だけを herdr で起動する。組み込み subagent 機能で代用しない。
- `agtask` があれば [references/agtask.md](references/agtask.md) に従い、起動前に構成案の版でタスクと依存を登録する。子に claim・証拠・提出を記録させ、`done` はレビュアーの accept だけで決める。
- 計画・調査 → 実装 → レビューの依存を守る。CLI 作業は必要な段階で渡す。独立した仕事だけ並列化する。
- 子へ目的、入力、担当ファイル、書込可否、完了条件、返答形式、タスク ID、親の通知先 pane ID を渡す。「追加委譲・モデル変更は禁止。担当外の問題は親に返す」も伝える。
- 完了待ちの polling は禁止。状態・出力・ファイルを繰り返し確認せず、`agent wait` や `agent prompt --wait` も使わない。agtask の参照も同じ。親は他の作業を進めるか、子からの通知を待つ。
- 子は herdr skill（`herdr --skill`）を読み、完了時に親へ herdr で完了メッセージを送る。失敗・判断待ちも同じ経路で通知し、親の応答を待たず制御を返す。
- 同じファイルを同時編集させない。共有 cwd では担当を分け、重なる変更は直列化する。
- 通知にはタスク ID、子の名前、結果・根拠・変更ファイル・検証結果・未解決点を短く含める。親は通知を受けて差分と成果物を確認する。
- 失敗時はログを確認し、同じ構成内の修正は `max_fix_rounds` まで。超過時は状況と次案を返す。
- 台数・並列上限・モデル・args・担当範囲・権限を変える場合は差分を示して再承認を待つ。利用不能でも無断で代替しない。
- 構成承認は子の操作権限を拡張しない。権限確認を自動回答したり、sandbox を無効化したりしない。
- 再開時は `agtask handoff`（あれば）を読み、承認済みの版・構成と既存の pane を照合し、重複起動を避ける。最後に成果・検証・未完了事項を報告する。
